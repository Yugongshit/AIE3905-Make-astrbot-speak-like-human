**[打开控制面板使用指南：上传记录、管理群开关、审核表达](docs/panel.md)**

**0.4.0：两个明确入口 + 预览与再次确认。** 更新并刷新页面后，从左侧 **“插件可视化视图” → “表达学习控制台”** 进入。“教它怎么说话”学习自然表达；“熟悉工作环境”学习汽配术语、别名、部件区别与流程。选择文件不会上传，点击预览后还要确认学习，传错可取消或更换。

**[工作环境学习指南：从聊天到可复用的概念](docs/auto-parts-knowledge.md)** · [虚构群聊格式示例](examples/auto_parts_chat.txt) · [知识 JSON 示例](examples/auto_parts_knowledge.json)

面板包含记录投喂、逐群学习/表达/知识开关、群备注、表达审核与评分、知识分类/来源/有效期、批量审核、导出和检索试验。[查看工作环境知识库预览](docs/images/auto-parts-knowledge-panel.png) · [表达面板预览](docs/images/learning-panel.png)。

也保留群内命令入口：发送 **`/学习`** 打开菜单。[查看命令使用指南](docs/learning.md) · [下载示例文件](examples/dialogues.json)。

让买家和供应商群里的机器人说话自然一点：少些客服套话，回应具体问题，必要时接住情绪。继续使用 AstrBot 已配置的模型，包括你的 `deepseekprov4`；插件不接管业务流程，也不额外发起一次模型调用。

“学习”通过**不断积累、检索和调整表达样例**实现。导入好对话、纠正一次回复后，后续请求就能参考新表达，重启后仍保留。它不修改 DeepSeek 的模型权重，也不承诺仅靠增加记录就一定越说越好；素材质量和人工反馈决定效果。

**工作环境与表达分开：**环境入口从聊天中识别可复用的术语、名称关系、部件区别、工作流程与沟通规则，提取结果先待审。观察某个词不代表已经证实其含义；别名不能仅凭共现认定。具体交易的金额、库存、交期、订单及客户信息不随原始群聊保存到环境库。各群的数据与约定隔离。

## 安装

需要 Python 3.12+、AstrBot `>=4.29.1,<5`。当前已使用 AstrBot 4.29.1 的真实 SDK 验证。

1. 打开 AstrBot 管理面板，进入插件管理，找到“从链接安装”或使用 GitHub 仓库链接的安装入口（不同版本名称可能略有不同）。
2. 粘贴下面的仓库地址，完成安装：

   ```text
   https://github.com/Yugongshit/AIE3905-Make-astrbot-speak-like-human
   ```

3. 确认插件列表出现“好好说话 · 表达学习”并已启用。在插件配置里可以填写生效群号；留空表示所有群。
4. 在 AstrBot 设置中配置管理员账号，并让目标群继续使用你已配置的 DeepSeek 提供商。插件不另填模型 API Key，也不改变模型名称。
5. 刷新管理面板，从左侧“插件可视化视图”打开“表达学习控制台”，选择目标群，再上传记录或开启学习收集。如果左侧暂未出现入口，先进入一次插件管理，再刷新页面。

学习管理命令只允许 **AstrBot 管理员** 操作，不自动等同于聊天平台的群管理员。默认唤醒前缀为 `/`；如果你修改过前缀，请换成自己的前缀或 @ 机器人后发送命令。

手动安装时，也可以将本插件目录放到 AstrBot 的 `data/plugins/astrbot_plugin_human_style/`，确认该目录直接包含 `main.py`、`metadata.yaml`、`_conf_schema.json` 与 `human_style/`，然后在控制台重载插件。无额外运行依赖。

默认所有群生效、私聊不生效，可以在插件配置中限定群号。插件不主动插话，不改变 AstrBot 的 @、引用或唤醒词规则。

网页控制台沿用 AstrBot 的管理登录和插件访问权限，无需另开端口或设置另一套账号。上传在本机浏览器里选文件即可；面板会先预览，确认后才入库。上传的样例后续会随模型请求发送给配置的模型提供商。

**从 0.1.0 / 0.2.0 / 0.3.0 更新：**在插件管理中更新插件（或安装新版 ZIP）后重新加载并刷新浏览器。已有 SQLite 表达数据和收集开关会保留。0.3.0 的历史交易条目仍可查看、导出、停用或删除，但即使已审核也停止参与回复检索；请重新投喂原始记录来提取环境概念。新安装默认关闭自动群聊收集；旧安装已有的配置继续沿用，请在控制台逐群确认开关。

如果卡片仍显示旧版：卡片右下角的圆形箭头是**重载本地文件**，不会下载新代码。请点击 **“⋯ → 更新”** 并确认更新，完成后刷新浏览器，检查卡片显示 **v0.4.0**。也可以下载上方 ZIP，在插件管理中使用“从文件安装”；无需先卸载旧版。

## 原始汽配群聊怎么导入

选择目标群 → 点击 **“② 熟悉工作环境”** → 选择 TXT 文件 → 点击 **“预览所选文件”** → 检查概念 → 点击 **“确认学习环境知识”** → 在弹窗核对群名、入口、文件名和条数并确认 → 去 **“工作环境知识库 → 待审核知识”** 审核。

选择或拖入文件只保留在浏览器，点击预览才上传解析；预览仅临时保留 15 分钟，不写入 SQLite。点击“取消 / 清空”、更换文件、切换入口或群会清除旧预览；最后弹窗也可以取消，继续修改。接口必须收到显式确认才会写库。

这版使用可检查的规则：群聊出现常见部件、品质或流程用语时，提供相应的行业解释候选；明确的“甲也叫乙”“甲不是乙”会形成名称关系候选。不会仅因同一行出现两个部件就判断为别名，也不会自动把一次交易变成群规则。未知别名或复杂新流程可能识别不到，可通过 JSON 模板或“新增规则 / 资料”补充。所有环境候选审核后才参与检索，修改后须重新审核。

不要求把原始 TXT 整理成问答。图片、语音占位符不能还原成配件知识；当前规则也不负责 VIN/OEM 适配查询。普通 TXT/Markdown 同样提取概念，不再把整篇交易文本切块存档。整理好的概念资料可使用 JSON / JSONL。

## 先喂一条，马上开始

在希望学习的群里，由管理员发送：

```text
/学习添加 怎么还没发货？ => 你是担心耽误后面的安排吧。供应商这边方便确认一下预计发货时间吗？
```

以后有人问类似问题，模型请求会带上这个表达参考。它只学说法，不把样例中的发货时间、金额或其他信息当作当前事实。

如果机器人刚才的回答不够自然：

```text
/学习纠正 你着急用吧，我们先把预计发货时间确认清楚。
```

这个命令会将**本群最近 10 分钟内最后一次完整模型回复所对应的问题**和你提供的新回复组成样例。多人同时问机器人时，建议使用明确写出问题的 `/学习添加`，避免指错目标。`/学习采纳` 则认可原回复，不修改措辞。机器人不会自动把自己的输出反复灌回学习库。

## 批量投放自然表达样例

以下群命令入口用于自然表达问答样例；原始群聊请使用面板的工作环境入口。表达样例接受 UTF-8 的 JSON、JSONL 和 TXT，每文件最多 2 MiB、2000 组问答。每组问题最多 500 字符，回复最多 1000 字符。整个文件解析成功后才写入；重复问答不重复积累。

**群内上传：**管理员先发送 `/学习上传`，再于同一群内 5 分钟内发送一个记录文件。文件会立即成为该群可参考的样例。这要求聊天平台适配器提供 AstrBot `File` 消息段；不支持群文件的平台可使用下方收件目录。

**收件目录：**把文件放入 AstrBot 根目录下的：

```text
data/plugin_data/astrbot_plugin_human_style/inbox/
```

然后在目标群发送 `/学习导入 历史记录.json`。只接受这个目录内的文件名，不接受任意服务器路径或网址。收件目录只是入口，执行导入时所在群决定学习库归属。

推荐 JSON：

```json
[
  {
    "question": "这个价格做不了。",
    "answer": "明白，这个价格确实有难度。要不先看看数量或规格有没有调整空间，双方再一起商量？"
  },
  {
    "question": "谢谢，解决了。",
    "answer": "解决了就好，后面有问题再喊我。"
  }
]
```

JSONL 每行一个 `{"question":"问题","answer":"希望学习的回复"}` 对象。

TXT：

```text
问：这个价格做不了。
答：明白，我们再看看有没有可以一起调整的地方。

问：谢谢，解决了。
答：解决了就好，后面有问题再喊我。
```

也接受 `{"messages":[{"role":"user","content":"问题"},{"role":"assistant","content":"希望学习的回复"}]}`。仅提取相邻的 user→assistant 问答；system/tool 消息不会被学习，并打断配对。这里的 assistant 表示“希望机器人学习的回答”，可以由你将历史中优秀的人类回复整理而来。任意微信/QQ原始导出并不都支持，请先整理成上述格式；插件不会猜哪位群成员的每句话都值得模仿。

`examples/dialogues.json` 提供三条演示素材，安装时不会自动灌入任何群。

## 从群聊继续积累

先在控制台“群与开关”中，为需要的群开启“从这个群学习”。新安装默认关闭，旧版本已有设置沿用。开启后，会从新消息提取待审环境概念；不同发言者在 180 秒内前后发言时，还会生成一个**粗略表达候选**。它可能并非问答，也可能有反讽或不合适的话，因此只进入待审区，不参与生成。每群最多保留最新 200 条候选。

在“表达库与审核”选择“待审核候选”，点击“通过并学习”即可生效；也可以使用下面的命令。

```text
/学习待审
/学习通过 12
```

通过后，编号 12 的候选才成为表达参考。无需模型训练或重启。

```text
/学习评分 12 +1
/学习评分 12 -1
/学习删除 12
```

评分会影响检索排序；权重从 1 开始，最多为 10，降至 -2 后停止参考。删除可移除样例、候选或停用记录。导入重复内容不会自动复活已有的候选或停用记录。

| 命令 | 用途 |
| --- | --- |
| `/学习` | 打开学习菜单，与 `/学习帮助` 相同 |
| `/学习帮助` | 查看入口和命令 |
| `/学习添加 问题 => 回复` | 直接添加一组认可的表达 |
| `/学习上传` | 允许本人随后上传一个记录文件 |
| `/学习导入 文件名` | 从收件目录批量导入 |
| `/学习样例` | 查看最近 10 条生效样例及编号 |
| `/学习待审` | 查看最近 10 条候选及编号 |
| `/学习通过 编号` | 让候选生效 |
| `/学习采纳` | 认可本群最近一次完整模型回复 |
| `/学习纠正 更好的回复` | 将自己的改写作为学习样例 |
| `/学习评分 编号 +1或-1` | 调整参考权重 |
| `/学习删除 编号` | 移除记录 |
| `/学习收集 开启或关闭` | 为当前群开启或关闭候选收集，设置会保留 |
| `/学习状态` | 查看生效、待审、停用数量及收集状态 |

表格中命令参数之间需加空格。默认唤醒前缀为 `/`；若在 AstrBot 修改过前缀，请使用你的配置。

## 模块结构

```text
main.py                  AstrBot 命令、群消息接收、模型请求钩子
human_style/records.py   JSON / JSONL / TXT 解析、长度限制、基础脱敏
human_style/memory.py    SQLite 持久化、去重、检索、评分与删除
human_style/service.py   导入接口与群聊候选收集
human_style/prompts.py   自然表达规则与有长度预算的样例上下文
human_style/panel.py     带鉴权的面板接口、群发现、预览与确认导入
human_style/knowledge.py 原始群聊概念提取、术语/区别/流程库、审核与检索
views/learning/          控制台 HTML、CSS 和 JavaScript，无前端构建依赖
```

回复路径：当前问题 → 分别检索表达样例与已审核环境概念 → 追加表达指导与工作环境参考 → AstrBot 原有模型调用。原有人设、对话历史、业务工具和模型选择保留。检索暂时不可用时，退回基础语气规则。

这一版不依赖向量模型：使用中文双字及英文词匹配、人工评分和新近程度排序。每次从高权重 500 条与最近 500 条的并集中检索，最多 1000 条；默认选 4 条参考，样例 JSON 总预算约 2200 字符，避免历史记录不断挤满上下文。大量素材和同义改写的召回效果仍有提升空间，后续可在 `Memory.retrieve` 替换为语义检索。

数据存于 `data/plugin_data/astrbot_plugin_human_style/expression_memory.sqlite3`，按平台实例、机器人账号和群隔离，同群不同成员共享表达库。群列表、学习开关、自然表达开关、备注、样例与面板导入统计均持久保存。备份时停止插件后复制整个插件数据目录；更新代码时保留它。临时的上传等待状态、反馈目标和未确认的导入预览不跨重启保留。

OneBot 可读取平台群列表；QQ 官方等未提供统一群列表的平台展示插件收到过消息的群。群未出现时，让该群发一条机器人能收到的消息再刷新。面板会注明发现来源，不能据历史记录保证机器人当前仍在群里，也不能保证列表完整。

基础脱敏会替换手机号、邮箱、部分证件号和连续长号码；**不能完整识别姓名、地址或业务敏感信息**，导入前仍应整理素材。样例内容会随模型请求发送给 AstrBot 中配置的模型提供商。样例被标明为表达数据而非指令，但提示词边界不能保证抵御所有恶意素材，管理员应导入可信内容。

环境入口提取原始群聊时只保留概念及最少用语证据、来源行号和观察时间，不保留原始交易正文或发言人身份。JSON、手工录入和表达入口仍需自行检查内容；基础脱敏不是完整匿名化。原始客户聊天不应提交到公开仓库或打进分享安装包。

## 开发和验证

```bash
python -m venv .venv
.venv/bin/python -m pip install -r requirements-dev.txt
.venv/bin/python -m pytest -q
.venv/bin/ruff check .
.venv/bin/ruff format --check .
```

测试覆盖批量导入、错误文件不部分入库、去重、并发写入、持久化、群隔离、候选审批、权重变化，以及使用真实 AstrBot SDK 的消息组件、命令和请求/响应钩子。测试不调用外部模型。

面板测试还使用真实 AstrBot Web 路由、鉴权、文件消息和插件视图资源服务，验证预览未入库、确认导入、跨群/跨账号预览隔离、两个独立开关，以及 0.1.0 数据升级。

浏览器集成验证（需要 Chromium）：

```bash
# 如已安装系统 Chromium，可使用其可执行文件路径；否则先执行 .venv/bin/playwright install chromium
.venv/bin/python tests/browser_smoke.py --browser-path /usr/bin/chromium
```

脚本使用临时数据和本机临时端口，在与 AstrBot 一致的 iframe 沙箱中验证上传、开关、改写、导出和删除，结束时停止测试服务。不提供面向用户的独立网页服务。

分享安装包可运行 `python scripts/build_plugin.py`，ZIP 会生成在 `dist/`。安装包只包含插件代码、面板与说明，不包含本地学习数据和测试运行产物。

这些测试验证插件行为，不证明真实回复已经达到你的语气要求。实际验收建议选择你们群里的典型问题，导入少量优质对话后对比回复，再通过纠正和评分调整。
